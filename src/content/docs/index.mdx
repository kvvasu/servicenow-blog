## Start from a record

Most of these notes start with a query. Run this in a background script or the
Xplore console on a sandbox instance, then read the result before you change
anything. `GlideRecordSecure` applies the caller's access rules, which is what you
want when the answer depends on who is asking.

<Code
	code={`var gr = new GlideRecordSecure('incident');
gr.addQuery('active', true);
gr.addQuery('assignment_group.name', 'Service Desk');
gr.setLimit(5);
gr.query();

while (gr.next()) {
  gs.info(gr.number + ' | ' + gr.short_description + ' | ' + gr.sys_updated_on);
}`}
	lang="javascript"
	title="glide-record-read.js"
/>

## How to read this site

Facts here — table names, field names, code snippets, links — come from public
sources and from notes taken while working with the platform. The explanations
are mine. Anything that depends on a release number belongs in a release note,
not a blog post, so check the official documentation for your own instance
before you rely on it.
