Administration work is mostly reversible if done in order: understand the existing configuration, change one thing, verify, then record it. This page covers the core areas where that order matters most.

Who should watch the Training:
### GETTING STARTED
A getting-started path for a system administrator begins with architecture: the instance stack, the database, and how a request reaches a business rule. Only after that does g_form behaviour or a workflow diagram make sense. Training that starts at the feature tour leaves gaps, because the learner cannot explain why two records behave differently. Build the platform model first, then attach features to it.
